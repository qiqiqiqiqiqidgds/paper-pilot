## 3. 缺陷详情

### BUG-1（P0 · Critical）：侧边栏切换论文不卸载旧视图，`<main>` 面板不断累积

- **现象**：每次在左侧论文库选中/切换/删除论文后，中部面板会**追加**一个新的查看器面板，旧面板（空态、PDF 阅读器、DOCX 占位）不被移除，全部以兄弟节点并排堆叠，越点越多。用户手动复现确认："多次点击左边栏会不断的重复，理论上应该是点击之后直接切换"。
- **复现步骤**：
  1. 打开 http://localhost:3000（干净状态，容器内 1 个 `<main>` 空态）；
  2. 单击论文库中任意一篇论文；
  3. 再次切换/删除论文，重复多次。
- **实测证据**（只读 DOM 探测）：
  - 干净状态：1 个 `<main>`；单击一次后：2 个 `<main>`（空态残留 + 新 PDF 阅读器）；
  - 多次操作后曾出现 **6 个并列 `<main>`**：空态 ×1 + PDF 阅读器 ×3（缩放分别被挤压为 53%/21%/3%）+ DOCX 占位 ×2（见截图）；
  - 删除论文后同样累积：2 个空态 + 1 个残留 DOCX 占位（见截图 t14）。
  - **React fiber 探针**：容器 fiber 只有 4 个子节点（侧栏 / 1 个带 key 的 ErrorBoundary>PDFViewer / 分割条 / AI 面板），即 **React 虚拟树是正确的，DOM 中旧节点成为孤儿未被移除**。
- **影响**：布局被挤压变形、PDF 过小不可读、空态/上传按钮常驻、多次操作后页面不可用；同时是内存/DOM 泄漏。
- **定位线索**（供修复参考，未做代码改动）：页面中查看器由 `<ErrorBoundary key={currentPaperId ?? "no-paper"}><PDFViewer /></ErrorBoundary>` 包裹（`frontend/src/app/page.tsx:68`）；keyed 重挂载路径下旧宿主节点未被移除。建议优先检查 ErrorBoundary 类组件与 keyed remount 的组合、react-pdf 动态导入版本兼容性，以及是否存在外部代码移动/克隆 DOM 节点。

### BUG-2（P1 · High）：「对比」Tab 联网对比两次尝试均失败（502）

- **现象**：点击「联网对比」→"搜索中"约 60–90s → 面板显示 **"❌ 联网搜索失败，请稍后重试"**。重试一次同样失败。
- **后端日志定位出两个叠加原因**：
  1. **arXiv 网络连通性不稳定（环境因素）**：`Arxiv 搜索失败（重试 2 次后放弃）: All connection attempts failed`（httpx 连不上 export.arxiv.org；同一台机器 curl 直接请求返回 HTTP 200、耗时 6.7s，无代理环境变量）。应用层重试 3 次与错误提示行为正确。
  2. **LLM 对比输出 JSON 解析失败（应用健壮性问题）**：一次尝试中 arXiv 初始化成功，但 LLM 返回的对比 JSON 解析失败，后端记录 `对比分析失败: LLM 返回的不是有效 JSON` → `POST /api/compare 502`。值得注意的是：拆解/创新/漏洞的同类 JSON 解析失败有重试兜底最终成功（日志中大量 `JSON 解析失败: JSONDecodeError（长度=…，前 120 字='```json…'`），而 `/api/compare` 路径无兜底直接失败。
- **次要问题**：LLM 输出解析失败时，前端统一显示"联网搜索失败"，错误语义不准确（误导排查方向）。
- **影响**：核心卖点功能"相关工作对比 + 对比表"当前环境下不可用；并阻塞了"多篇论文对比"入口的 GUI 验证。
- **建议**：为 `/api/compare` 增加与其他分析路径一致的 JSON 解析重试/围栏剥离兜底；排查后端 httpx 对 export.arxiv.org 的连通性（IPv6/双栈、超时设置）；前端错误文案区分"搜索失败"与"分析生成失败"。

### BUG-3（P2 · Medium）：手动缩放被"适合宽度"自动重算覆盖

- **现象**：PDF 缩放 33% → 放大两次至 53%（正常），随后点击一次"缩小"后显示 **50%**（预期 43%）。
- **分析**：与源码 A6 注释描述的历史回归一致——画布渲染触发布局宽度变化后，`ResizeObserver` 的"适合宽度"重算覆盖了用户手动缩放值（`frontend/src/components/pdf-viewer.tsx:159-185`）。
- **影响**：手动缩放体验不可预期（中等）。

### 次要观察（不计为缺陷）

1. **导出下载瞬态文件名**：导出 Markdown 后约 41s 内落盘文件为 `*.tmp`，之后完成重命名为 `<论文名>-分析报告.md`（内容 13.9KB 完整正确）。PPT 下载文件名始终正常。疑似浏览器下载管理器行为，建议在真实 Chrome 复核。
2. **LLM JSON 解析噪声**：MiniMax-M3 输出常带 ```json 围栏/思考标签，后端对拆解/创新/漏洞路径均有重试兜底（最终结果正确），但每次都打 ERROR 级日志，建议降噪（解析成功后降为 DEBUG）。
3. **Playwright 自动化点击超时而 CUA 坐标点击可用**：页面可能存在持续重渲染（与 BUG-1 的重挂载相关），导致自动化框架的元素稳定性检查永不通过——修复 BUG-1 后建议复测可测试性。
4. **测试环境事件**：一次浏览器截图管线卡死（30s 超时不可恢复），重开标签页后恢复；与页面持续重渲染疑似相关。

## 7. 结论与建议

**结论**：核心阅读-分析链路（上传解析 → 论文库 → PDF 对开视图 → 拆解/创新/漏洞 → 引用联动高亮 → PPT 一键生成/导出）在真实 LLM 下整体可用且质量较高；但存在 1 个 P0 渲染缺陷（BUG-1）使多轮切换后页面不可用，1 个 P1 功能失败（BUG-2 对比），当前状态**不建议直接演示/发布**，修复两项后复测。

**建议修复顺序**：
1. **P0 BUG-1**：修复 keyed ErrorBoundary 重挂载导致的 DOM 孤儿累积（page.tsx 查看器挂载路径）；
2. **P1 BUG-2**：/api/compare 增加 JSON 解析兜底重试 + 排查后端到 arXiv 的连通性（IPv6/超时）+ 前端错误文案区分；
3. **P2 BUG-3**：隔离用户手动缩放与自动适宽（A6 回归注释的遗留场景）；
4. 降噪 LLM JSON 解析日志；在真实 Chrome 复核导出文件名与上传 GUI 全链路。

## A1. BUG-1（P0）DOM 孤儿累积 — 已修复 ✅

**改动**：
- `frontend/src/components/error-boundary.tsx`：新增 `resetKey` prop（React 官方推荐的错误边界复位模式，`getDerivedStateFromProps` 中比较 prevResetKey 清除错误态）。
- `frontend/src/app/page.tsx`：查看器与 AI 面板两处 `<ErrorBoundary key={currentPaperId ?? "no-paper"}>` 改为 `resetKey={...}`，不再重挂载子树。

**原理**：keyed 重挂载 + `next/dynamic` 懒加载的 PDFViewer 组合会使旧 `<main>` 宿主节点残留为孤儿并随每次选择/切换/删除不断累积（React fiber 树正确、DOM 错误）。改为 resetKey 后既保留"切论文复位错误边界"的原有意图（F 修复），又彻底消除重挂载。

**回归验证**（1440×900，真实点击）：
- 干净状态选中 DOCX → **mains=1**（修复前为 2）
- DOCX↔PDF 来回切换 5 次 → **mains 恒为 1**（修复前累积至 6）
- 删除论文后再选 → mains=1（修复前为 3）
- PDF 面板独占中部全宽，适宽缩放恢复到 72%（修复前被挤到 3%–53%）

## A2. BUG-2（P1）联网对比失败 — 已修复 ✅

**根因修正**：测试阶段记录的"两个叠加原因"之一（arXiv ConnectError）与重试期间的一次 LLM JSON 截断。进一步分析后端日志中"长度=647~8759"的异常短输出确认：**MiniMax-M3 的 `<think>` 推理消耗 max_tokens 预算导致 JSON 中途截断（finish_reason=length）**，旧解析兜底（贪婪正则）无法恢复。

**改动**：
- `backend/app/services/llm_client.py`：
  - 新增 `_strip_code_fence()`（剥离 ```` ```json ```` 围栏）、`_repair_truncated_json()`（单遍扫描：字符串/转义/括号栈/期望值状态，回退到最后一个安全值边界后按栈逆序补全闭合符）、`_parse_json_lenient()`（宽松解析管线）；
  - `chat()` 重构为 `_chat_content()` 返回 `(content, finish_reason)`；
  - `chat_json()`：解析失败且 `finish_reason=length` 时 **max_tokens 加倍（上限 32768）完整重试一次**；解析失败的中间日志由 ERROR 降为 WARNING，仅最终失败打一条 WARNING（日志降噪）。
- `backend/app/services/search_client.py`：arXiv 客户端超时分级（connect 单独 10s）+ `AsyncHTTPTransport(retries=2)` 连接级重试，吸收瞬态 ConnectError。
- 前端无需改动：`api.ts` 的 `extractError` 已透传 FastAPI `detail`，测试中两种文案差异对应不同请求的真实失败点。

**回归验证**：GUI 点击「联网对比」→ 约 90s 后完整返回：主论文摘要 + 5 篇 arXiv 相关工作（方法/数据集/结果/优劣势）+ 对比表 + 整体对比，`POST /api/compare 200 OK`；期间一次 arXiv ConnectTimeout 被 1s 重试吸收；日志无 JSON 解析 ERROR。
（修复后联网对比成功，截图略）

## A3. BUG-3（P2）缩放异常 — 已修复 ✅（根因修正）

**根因修正**：测试阶段推测"适宽重算覆盖手动缩放"有误。真实原因：缩小按钮实现 `Math.max(0.5, zoom - 0.1)` 存在 **50% 硬下限**，从 53% 点缩小得 50%（0.43 被钳制），且按钮在边界不禁用，用户无从得知已到底。

**改动**：`frontend/src/components/pdf-viewer.tsx` 缩放区间 [0.5, 3] 边界处禁用 缩小/放大 按钮（与 clamp 语义一致）。

**回归验证**：62% → 52% → 50% 后「缩小」按钮变为 disabled ✓。
