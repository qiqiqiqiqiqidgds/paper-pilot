## 二、前端修复(12 项 + 1 个新发现缺陷)

### P0-1 `<Document options>` 未 memo 化 → 整本反复重载
- **位置**:`frontend/src/components/pdf-viewer.tsx`
- **修复**:options 提为模块级常量 `DOCUMENT_OPTIONS`(react-pdf 的 loadDocument effect 依赖其引用,引用稳定即不再 destroy/重载);"适合宽度"只在每个文档(pdfUrl)首次加载时执行(`lastFittedFileRef` 守卫);顺修 onLoadSuccess 内 `const numPages` 遮蔽同名 state(改名 total)。
- **浏览器实测**:点"放大" 130%→140% 在 400/1200/2700ms 均稳定保持不回弹(修复前 200ms 内被打回 100%);翻页无闪白。

### P1-1 compare/PPT loading 锁随组件卸载丢失
- **修复**:锁上收 `paper-store`(`compareStartedAt` / `pptStartedAt`,时间戳兼所有权令牌);入口同步查锁+置锁(防双击);finally 仅当令牌仍归属本任务才清(防旧任务误清新任务锁);setCurrentPaper / removePaper 三处复位。
- **验证**:检查员对 A/B 任务交错场景反例推演无懈可击;浏览器实测捕获到生成中状态(aria-busy + "已等待 N 秒",计时以 store 发起时刻为基准,切书签带重挂不归零)。

### P1-2 同页多次引用跳转旧高亮残留
- **修复**:`lastHighlightedEl`(单元素)→ `lastHighlightedEls`(整个 run 数组);clearHighlight 逐元素判 document.contains 后移除两个 class;渐隐对全量生效,timer 槽位语义保留。
- **浏览器实测**:同页连点两次恒为 3 个高亮(不叠加为 6),跨页往返无残留。

### ★ 新发现缺陷:引用按钮从不传递引文文本(高亮链路断裂的另一半根因)
- **发现过程**:P0-1 修复后浏览器复测,点击引用跳页正常但高亮仍为 0、无报错。挂探针抓到 `paperpilot:jump-to-pdf` 事件 detail 只有 `{ page: 2 }` 没有 text——`JumpButton.handleJump` 只调 `onJumpToPDF?.(page || 1)`,而 pdf-viewer 高亮入口条件 `highlightText.length > 5` 对 undefined 静默失败。原报告 T9"高亮从未出现"实际是两个缺陷叠加,单修 P0-1 不会让高亮工作。
- **连带发现**:PDF 文本层 span 拼接在行边界丢空格(实测 "five hours.Large"、"single-passsummarization"),按空白归一化匹配会漏判跨边界候选。
- **修复**:`JumpButton` 新增 text prop 并在 ZhuQuote / flaws-view(evidence)/ innovation-view(evidence)三处透传;`applyHighlight` 增加"去全部空白 + toLowerCase"兜底比较(空串短路防 `includes("")` 恒真陷阱;主匹配路径不变)。
- **流程**:修改子代理 → 独立检查子代理 PASS(逐候选推演 + Node 逐字模拟)→ 浏览器复测:**点引用跳页且高亮出现**(3 个 span 命中目标引文,修复前 3 秒轮询恒为 0)。

## 五、遗留观察项(非阻塞,无需返工)

4. tiktoken 仅从依赖清单移除,venv 内未卸载(避免动运行环境,可选 pip uninstall)。
5. 两处注释仍提及已删除的 ResizeHandle(mobile-toggle.tsx / use-keyboard-shortcuts.ts,纯 cosmetic)。
